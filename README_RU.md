# Churn Retention Copilot

[English](README.md) | [Русский](README_RU.md)

AI-копилот для анализа риска оттока клиентов и поддержки решений по удержанию.

Проект объединяет ML-модель прогнозирования оттока, SHAP-объяснения, semantic RAG по политикам удержания, структурированные рекомендации LLM, multi-turn чат, FastAPI, Streamlit и Docker.

## Что делает проект

Для заданного профиля клиента система:

1. Рассчитывает вероятность оттока с помощью CatBoost.
2. Объясняет прогноз через SHAP.
3. Формирует структурированный профиль риска.
4. Находит релевантные политики удержания через semantic search.
5. Передаёт найденные политики в LLM и генерирует рекомендацию по удержанию.
6. Поддерживает дополнительные вопросы по клиенту в multi-turn чате.
7. Предоставляет доступ к пайплайну через Streamlit и FastAPI.

## ML и объяснимость

CatBoost используется для расчёта вероятности оттока клиента.

После получения прогноза SHAP определяет вклад каждого признака в результат модели. Факторы разделяются на две группы:

- `risk_drivers` — признаки, которые сдвинули прогноз модели в сторону оттока;
- `protective_factors` — признаки, которые сдвинули прогноз в противоположную сторону.

SHAP-интерпретация рассматривается как объяснение поведения модели, а не как доказательство причинно-следственной связи.

## Semantic RAG

Политики удержания хранятся в виде структурированных документов.

Каждая политика содержит:

- описание ситуации;
- разрешённые действия;
- ограничения.

Документы преобразуются в embeddings с помощью `all-MiniLM-L6-v2` и сохраняются в локальной векторной базе Qdrant.

Для каждого клиента `RiskProfile` преобразуется в текстовый поисковый запрос, содержащий вероятность оттока и основные risk drivers.

Далее Qdrant выполняет semantic search и возвращает наиболее релевантные политики удержания.

Найденные документы передаются LLM как разрешённый операционный контекст.

LLM получает инструкции:

- использовать только действия, явно разрешённые найденными политиками;
- соблюдать ограничения политик;
- не придумывать скидки, платёжные планы и другие действия;
- не интерпретировать SHAP как причинность.

Например, если пользователь спрашивает:

```text
Can we offer a 50% discount?
```

а найденные политики не разрешают скидку, копилот откажется от такого действия и предложит разрешённую альтернативу.

## FastAPI

Запуск API:

```bash
python -m uvicorn churn_copilot.api:app --reload
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

Доступные endpoints:

```text
GET  /health
POST /analyze
POST /chat
```

### `/analyze`

Принимает признаки клиента и запускает полный пайплайн:

```text
CustomerFeatures
      ↓
CatBoost
      ↓
SHAP
      ↓
RiskProfile
      ↓
Qdrant RAG
      ↓
LLM
      ↓
CustomerAnalysis
```

Ответ содержит:

- вероятность оттока;
- risk drivers;
- protective factors;
- найденные retention policies;
- структурированную рекомендацию;
- сообщение для клиента.

### `/chat`

Позволяет задавать дополнительные вопросы по уже выполненному анализу.

В запрос передаются:

- текущий `CustomerAnalysis`;
- вопрос пользователя;
- история диалога.

Это позволяет копилоту поддерживать multi-turn контекст и отвечать на связанные вопросы.

## Streamlit

Запуск пользовательского интерфейса:

```bash
streamlit run app.py
```

В интерфейсе можно:

- задавать параметры клиента;
- запускать churn-анализ;
- видеть вероятность оттока;
- получать объяснение результата;
- получать retention recommendation;
- просматривать технические SHAP-факторы;
- задавать дополнительные вопросы в чате.

## Docker

Сборка Docker image:

```bash
docker build -t churn-retention-copilot .
```

Запуск API:

```bash
docker run --rm --env-file .env -p 8000:8000 churn-retention-copilot
```

После запуска Swagger будет доступен по адресу:

```text
http://127.0.0.1:8000/docs
```

Qdrant-индекс создаётся во время сборки Docker image.

## Переменные окружения

Создайте `.env` на основе `.env.example`:

```text
OPENAI_API_KEY=your_api_key_here
```

Реальный `.env` не должен попадать в Git или Docker image.
